Older versions of this page explained how to enable **Bull Board** — `AP_QUEUE_UI_ENABLED`, `AP_QUEUE_UI_USERNAME`, `AP_QUEUE_UI_PASSWORD`, UI at `/api/ui` — to inspect the `workerJobs` job queue: stuck flow runs, delayed jobs, retry backoff.

**None of that exists in this codebase.** There is no job queue to inspect: executions run synchronously and in-process in the app container ([Workers](../architecture/workers)), and no route serves `/api/ui`. The `AP_QUEUE_UI_*` variables are still *defined* (the property system accepts them) but nothing reads them — setting them changes nothing.

## What to use instead

- **`GET /api/v1/health`** — the health endpoint, served by every container role (it is the only route a `WORKER` container registers). Use it for the app tier's liveness.
- **Execution results** — every operation is synchronous: a call either returned, failed with an error its caller can see, or the process died mid-flight ([Crash Recovery](../guarantees/crash-recovery)). There is no "stuck in queue" state to hunt for.
- **`429` + `Retry-After` responses** — the platform's honest "busy now" signal when a project is over its concurrency cap or the sync rate limit is hit. A project that suddenly 429s while little is executing is usually waiting on a concurrency slot held by a dead process: slots self-release after `AP_PROJECT_EXECUTION_CONCURRENCY_SLOT_TTL_SECONDS` (default 900 s). See [Manage Concurrency](../../admin-guide/guides/manage-concurrency).
- **`pool` log fields** — Postgres pool saturation is logged under the `pool` field group (startup budget, background errors, a 60-second snapshot); see [Postgres Connection Budget](../configure-operate/postgres-connection-budget#metrics).
