### Core

Identity and connectivity for the platform: the public URL, the keys that
protect connections and tokens, and telemetry.

| Variable | Description | Default |
|---|---|---|
| ❗ `AP_FRONTEND_URL` | The public URL used to build redirect URLs and webhook URLs. It must be reachable by third parties for webhooks and app triggers to work. | `None` |
| ❗ `AP_ENCRYPTION_KEY` | 32-character (16-byte) hexadecimal key used to encrypt connections. Generate one with `openssl rand -hex 16`. | `None` |
| ❗ `AP_JWT_SECRET` | 32-character hexadecimal key used to sign JWT tokens. Generate one with `openssl rand -hex 32`. | `None` |
| `AP_CONFIG_PATH` | Path where the PGLite database and local settings are stored. | `~/.activepieces` |
| `AP_INTERNAL_URL` | (Beta) Internal URL used for SSO authentication, e.g. `https://demo.activepieces.com/api`. | `None` |
| `AP_TELEMETRY_ENABLED` | Collect anonymous telemetry. | `true` |
| `AP_TELEMETRY_INCLUDE_PII` | Opt in (issue #406) to sending user identity fields — email, first name, last name — along with anonymous telemetry. Without it, usage telemetry still flows but identity fields are stripped. | `false` |
| `AP_PORT` | Port the API server listens on. Also used to build the worker role's callback URL (`http://127.0.0.1:<port>/api`). | `3000` (the Docker entrypoint defaults it to `80` inside the container) |
| `AP_EDITION` | Feature set to boot: `ce` (Community), `ee` (Enterprise), or `cloud`. The enterprise and cloud editions register the SSO/SAML, SCIM, platform-plan, license-key, and embed-subdomain modules on startup. | `ce` |
| `AP_ENVIRONMENT` | Deployment mode: `prod`, `dev`, or `test`. `dev` skips serving the built console (run the web dev server instead) and warns that only the pieces in `AP_DEV_PIECES` are listed; `test` skips SMTP delivery, runs PGLite in memory, and skips the S3 startup validation. | `prod` |
| `AP_JWT_ISSUER` | `iss` claim for newly issued JWTs. Verification keeps accepting the legacy `activepieces` issuer until the configured value equals it, so tokens minted before an issuer change keep working (issue #373). | `activepieces` (legacy upstream value) |
| `AP_SENTRY_DSN` | Sentry DSN for server-side error capture. | `None` |
| `AP_FRONTEND_SENTRY_DSN` | Sentry DSN exposed to the web console for client-side error capture. | `None` |
| `AP_API_KEY` | Platform admin API key. Gates the admin endpoints (sent as the `api-key` header, compared in constant time; cloud edition) and authenticates the pieces CLI (`publish-piece`, `sync`). `tools/deploy.sh` generates one into the root `.env`. | `None` |

<Warning>
`AP_FRONTEND_URL` is essential for webhooks and app triggers. It must be
accessible to third parties so they can send data.
</Warning>

The default URL is the machine's IP address. If that address isn't reachable
from the internet, set `AP_FRONTEND_URL` explicitly. For local development you
can expose the frontend port (4200) with a tunneling service such as
[ngrok](https://ngrok.com/).

### Logging & observability

Controls the server's log pipeline: level, formatting, sampling, and where logs
are shipped. Remote drains are resolved in order — **Axiom → HyperDX → Loki →
Better Stack → OTLP** — and only the first fully-configured one is used.
`AP_LOG_FILE` writes local files *in addition to* any remote drain.

| Variable | Description | Default |
|---|---|---|
| `AP_LOG_LEVEL` | Minimum log level: `error`, `warn`, `info`, `debug`, or `trace`. | `info` |
| `AP_LOG_PRETTY` | Pretty-print logs on the console instead of raw JSON. | `false` |
| `AP_LOG_FILE` | Write NDJSON log files under `.evlog/logs` (kept for 14 files, oldest rotated out). Development-oriented; also enables the browser client-logs endpoint on non-cloud editions. | `false` |
| `AP_LOG_SAMPLE_RATE_INFO` | Percentage (0–100) of `info`-level events kept by the sampler. `warn` and `error` events are always kept. | `100` |
| `AP_LOG_KEEP_SLOW_MS` | Events slower than this (in milliseconds) are always kept, even when the sampler would drop them. | `2000` |
| `AP_AXIOM_TOKEN` | Axiom API token. Both this and `AP_AXIOM_DATASET` must be set for the Axiom drain to activate. | `None` |
| `AP_AXIOM_DATASET` | Axiom dataset that logs are shipped to. | `None` |
| `AP_HYPERDX_TOKEN` | HyperDX API token (enables the HyperDX drain). | `None` |
| `AP_LOKI_URL` | Loki base URL; batches are pushed to `<url>/loki/api/v1/push`. | `None` |
| `AP_LOKI_USERNAME` | Basic-auth username for the Loki endpoint. | `None` |
| `AP_LOKI_PASSWORD` | Basic-auth password for the Loki endpoint. | `None` |
| `AP_BETTERSTACK_HOST` | Better Stack host. Both this and `AP_BETTERSTACK_TOKEN` must be set for the Better Stack drain to activate. | `None` |
| `AP_BETTERSTACK_TOKEN` | Better Stack source token. | `None` |
| `AP_OTEL_ENABLED` | Export logs via OTLP (OpenTelemetry). Only used when no other drain is configured. | `false` |

### Database

Inboxfm Connect stores its data in PostgreSQL (recommended for production) or an
embedded PGLite database. Set the connection with discrete fields or a single
`AP_POSTGRES_URL`.

| Variable | Description | Default |
|---|---|---|
| `AP_DB_TYPE` | `POSTGRES` for external PostgreSQL, `PGLITE` for the embedded database. `SQLITE3` is deprecated and auto-migrated to `PGLITE`. | `POSTGRES` |
| `AP_POSTGRES_URL` | Full connection string (e.g. `postgres://user:password@host:5432/database`). When set, the discrete fields below are ignored. | `None` |
| ❗ `AP_POSTGRES_HOST` | Hostname or IP address of the PostgreSQL server. | `None` |
| ❗ `AP_POSTGRES_PORT` | Port number of the PostgreSQL server. | `None` |
| ❗ `AP_POSTGRES_DATABASE` | Name of the PostgreSQL database. | `None` |
| ❗ `AP_POSTGRES_USERNAME` | PostgreSQL user. | `None` |
| ❗ `AP_POSTGRES_PASSWORD` | PostgreSQL password. Generate one with `openssl rand -hex 32`. | `None` |
| `AP_POSTGRES_USE_SSL` | Connect to PostgreSQL over SSL. | `false` |
| `AP_POSTGRES_SSL_CA` | SSL certificate (CA) used to connect to PostgreSQL. | `None` |
| `AP_POSTGRES_POOL_SIZE` | Maximum number of clients in the connection pool (per replica). | `10` (the `pg` driver default) |
| `AP_POSTGRES_IDLE_TIMEOUT_MS` | Idle timeout (ms) for pooled PostgreSQL connections. | `300000` |
| `AP_POSTGRES_CONNECTION_TIMEOUT_MS` | Bounded wait (ms) when acquiring a connection — both for opening a new physical connection and for queuing behind an exhausted pool. Turns "hangs forever" into an actionable timeout error. | `10000` |
| `AP_POSTGRES_MAX_CONNECTIONS` | The Postgres server's own `max_connections` capacity. Declaring it opts every app-role replica into the startup connection-budget check — see [Postgres Connection Budget](/install/configure-operate/postgres-connection-budget). Unset by default: **zero-setup, no check runs.** | `None` |
| `AP_POSTGRES_EXPECTED_APP_REPLICAS` | How many replicas run with `AP_CONTAINER_TYPE=APP` or `WORKER_AND_APP` (the only roles that open a Postgres pool). Only read when `AP_POSTGRES_MAX_CONNECTIONS` is set. | `1` |

### Redis & queue

Redis backs the BullMQ job queue. Connect with discrete fields, a single
`AP_REDIS_URL`, or Sentinel. The queue UI is an optional dashboard for
inspecting jobs.

| Variable | Description | Default |
|---|---|---|
| `AP_REDIS_TYPE` | Where Redis runs: `MEMORY` (in-process), `STANDALONE` (dedicated instance), or `SENTINEL`. | `STANDALONE` |
| `AP_REDIS_URL` | Full Redis connection URL. When set, all other Redis properties are ignored. | `None` |
| ❗ `AP_REDIS_HOST` | Hostname or IP address of the Redis server. | `None` |
| ❗ `AP_REDIS_PORT` | Port number of the Redis server. | `None` |
| ❗ `AP_REDIS_USER` | Username used to connect to Redis. | `None` |
| ❗ `AP_REDIS_PASSWORD` | Password used to connect to Redis. | `None` |
| `AP_REDIS_DB` | Redis database index to use. | `0` |
| `AP_REDIS_USE_SSL` | Connect to Redis over SSL. | `false` |
| `AP_REDIS_SSL_CA_FILE` | Path to the CA file for the Redis server. | `None` |
| `AP_REDIS_SENTINEL_HOSTS` | Comma-separated `host:port` pairs for Redis Sentinels, e.g. `sentinel-1:26379,sentinel-2:26379`. Requires `AP_REDIS_TYPE=SENTINEL`. | `None` |
| `AP_REDIS_SENTINEL_NAME` | Name of the master node monitored by the sentinels. | `None` |
| `AP_REDIS_SENTINEL_ROLE` | Role to connect to, either `master` or `slave`. | `None` |
| `AP_REDIS_FAILED_JOB_RETENTION_DAYS` | Days to retain failed jobs in Redis. | `30` |
| `AP_REDIS_FAILED_JOB_RETENTION_MAX_COUNT` | Maximum number of failed jobs to retain in Redis. | `100000` |
| `AP_QUEUE_UI_ENABLED` | Enable the queue UI (Redis only). | `true` |
| `AP_QUEUE_UI_USERNAME` | Username for the queue UI. Required when `AP_QUEUE_UI_ENABLED` is `true`. | `None` |
| `AP_QUEUE_UI_PASSWORD` | Password for the queue UI. Required when `AP_QUEUE_UI_ENABLED` is `true`. | `None` |

<Info>
If `AP_REDIS_URL` is set, all other **Redis properties are ignored**. The same
applies to `AP_REDIS_SENTINEL_HOSTS` when running in Sentinel mode.
</Info>

### Execution & sandboxing

Controls how flows run: the sandbox mode, per-process memory and concurrency,
run timeouts, and the network egress posture for user code. Read
[Sandboxing](/install/architecture/sandboxing) before changing `AP_EXECUTION_MODE`.

| Variable | Description | Default |
|---|---|---|
| `AP_EXECUTION_MODE` | Sandbox strategy: `UNSANDBOXED`, `SANDBOX_PROCESS`, `SANDBOX_CODE_ONLY`, or `SANDBOX_CODE_AND_PROCESS`. | `UNSANDBOXED` |
| `AP_CONTAINER_TYPE` | Which services run in the container: `APP` (API only), `WORKER` (worker only), or `WORKER_AND_APP` (both). | `WORKER_AND_APP` |
| `AP_WORKER_CONCURRENCY` | Concurrent jobs a worker processes at once. Each job uses one sandbox instance. | `5` |
| `AP_SANDBOX_MEMORY_LIMIT` | Maximum memory (KB) a single sandboxed engine process can use. Each process runs at most one execution at a time. | `1048576` |
| `AP_SANDBOX_PROPAGATED_ENV_VARS` | Comma-separated environment variables propagated into sandboxed code. For pieces, keep everything in the authentication object so it works across instances. | `None` |
| `AP_FLOW_TIMEOUT_SECONDS` | Maximum runtime for a single flow run, in seconds. | `600` |
| `AP_TRIGGER_TIMEOUT_SECONDS` | Maximum runtime for a trigger's polling, in seconds. | `60` |
| `AP_DEFAULT_CONCURRENT_JOBS_LIMIT` | Default maximum concurrent runs per project. Can be overridden per project in settings. | `5` |
| `AP_PROJECT_RATE_LIMITER_ENABLED` | Enforce per-project rate limits to prevent excessive usage. | `false` |
| `AP_PROJECT_RATE_LIMITER_MAX_REQUESTS` | Requests per window, per project. Comfortably covers a busy flow-builder session plus normal webhook/API traffic for one project. Only read when `AP_PROJECT_RATE_LIMITER_ENABLED` is `true`. | `300` |
| `AP_PROJECT_RATE_LIMITER_WINDOW_SECONDS` | Window (seconds) for `AP_PROJECT_RATE_LIMITER_MAX_REQUESTS`. | `60` |
| `AP_PROJECT_EXECUTION_CONCURRENCY_LIMITER_ENABLED` | Cap how many executions a single project can keep in flight at once (each trigger RUN holds one slot for its duration). Disabled by default so an existing deployment never starts rejecting requests it didn't reject before. | `false` |
| `AP_PROJECT_EXECUTION_CONCURRENCY_LIMIT` | Concurrent in-flight executions allowed per project when the limiter above is on. A project's concurrency-pool settings override this on the enterprise/cloud editions. | `5` |
| `AP_PROJECT_EXECUTION_CONCURRENCY_SLOT_TTL_SECONDS` | Backstop TTL for a project's execution slots. Refreshed on every acquire, so a live execution never expires — it only matters when a process dies mid-execution without releasing its slot. Keep it above `AP_FLOW_TIMEOUT_SECONDS` plus queueing overhead. | `900` |
| `AP_NETWORK_MODE` | Egress posture for user code. `STRICT` installs the engine's in-process SSRF guard, blocking outbound connections to private, loopback, link-local, and cloud-metadata IPs across every Node egress path (`axios`, `fetch`, `undici`, raw `http`/`net`). This is best-effort, in-process protection — enforce the real boundary in infrastructure (see [Network Security](/install/architecture/network-security)). `UNRESTRICTED` disables the guard. | `UNRESTRICTED` |
| `AP_SSRF_ALLOW_LIST` | Comma-separated IPs or CIDR ranges that bypass `AP_NETWORK_MODE=STRICT`, e.g. `10.0.0.5,10.10.0.0/24`. Only applies when `AP_NETWORK_MODE=STRICT`. | `None` |

#### Engine & sandbox internals

Read by the sandboxed engine child process. Mostly plumbing — the sandbox host
injects them per start, so there is normally no reason to set them by hand.

| Variable | Description | Default |
|---|---|---|
| `AP_BASE_CODE_DIRECTORY` | Directory the engine reads bundled flow-step code from. The sandbox host passes the per-flow code directory into the engine child; the default only applies when the engine runs without a sandbox host. | `./codes` |
| `AP_SANDBOX_WS_PORT` | Port of the parent's sandbox RPC websocket, which the engine child connects back to (the host picks a port per sandbox start). Also allowlisted for loopback connections by the SSRF guard. | `12345` (fallback when not injected) |
| `AP_SANDBOX_WS_TOKEN` | Token authenticating the engine child on the sandbox RPC websocket. Generated fresh by the sandbox host on every start — never set this manually. | `None` (auto-generated) |

### Limits & retention

Caps on file sizes, run-log size, webhook payloads, table sizes, and how long
run data is kept. The **Cloud** values and how these interact are covered in
[Limits](/install/reference/limits).

| Variable | Description | Default |
|---|---|---|
| `AP_EXECUTION_DATA_RETENTION_DAYS` | Days to retain execution data, logs, and events. | `30` |
| `AP_PAUSED_FLOW_TIMEOUT_DAYS` | Maximum pause duration for a paused flow, in days. Cannot exceed `AP_EXECUTION_DATA_RETENTION_DAYS`. | `30` |
| `AP_ISSUE_ARCHIVE_DAYS` | Issues not updated for this many days are automatically archived. | `7` |
| `AP_MAX_FILE_SIZE_MB` | Maximum size (MB) for files uploaded in steps or triggers. Larger files are rejected. | `25` |
| `AP_MAX_FLOW_RUN_LOG_SIZE_MB` | Maximum combined size (MB) of all step inputs and outputs in a single run. Exceeding it ends the run with `LOG_SIZE_EXCEEDED`. | `50` |
| `AP_FLOW_RUN_LOG_SLICE_THRESHOLD_KB` | Step outputs larger than this (KB) are offloaded to object storage instead of inlined in the run log. | `32` |
| `AP_FLOW_RUN_LOG_INPUT_TRUNCATE_THRESHOLD_KB` | Step inputs larger than this (KB) are replaced with a placeholder in the run log; the step still receives the full value at runtime. | `2` |
| `AP_MAX_WEBHOOK_PAYLOAD_SIZE_MB` | Maximum incoming webhook payload size (MB). Larger payloads are rejected with HTTP 413. | `25` |
| `AP_WEBHOOK_PAYLOAD_INLINE_THRESHOLD_KB` | Webhook payloads below this (KB) are stored inline in Redis; larger ones are offloaded to file storage to protect Redis memory. | `512` |
| `AP_WEBHOOK_TIMEOUT_SECONDS` | Default timeout for synchronous webhooks. Maximum 15 minutes; note Cloudflare caps it at 30 seconds. | `30` |
| `AP_MAX_RECORDS_PER_TABLE` | Maximum number of records per table. | `10000` |
| `AP_MAX_FIELDS_PER_TABLE` | Maximum number of fields per table. | `100` |

S3-compatible bucket.

| `AP_S3_ENDPOINT` | Endpoint URL of the S3-compatible service, e.g. `https://s3.amazonaws.com`. Not required if `AWS_ENDPOINT_URL` is set. | `None` |

| `AP_S3_ACCESS_KEY_ID` | Access key ID. Not required when `AP_S3_USE_IRSA` is `true`. | `None` |
| `AP_S3_SECRET_ACCESS_KEY` | Secret access key. Not required when `AP_S3_USE_IRSA` is `true`. | `None` |

### Email (SMTP)

Outbound mail for invitations, notifications, and password resets.

| Variable | Description | Default |
|---|---|---|
| `AP_SMTP_HOST` | SMTP server host, e.g. `mail.example.com`. | `None` |
| `AP_SMTP_PORT` | SMTP server port, e.g. `587`. | `None` |
| `AP_SMTP_USERNAME` | SMTP username. | `None` |
| `AP_SMTP_PASSWORD` | SMTP password. | `None` |
| `AP_SMTP_SENDER_EMAIL` | Email address that mail is sent from. | `None` |
| `AP_SMTP_SENDER_NAME` | Sender name shown on outgoing mail. | `None` |

SMTP is environment-variable-only — platform-admin SMTP configuration was
removed in [0.73.0](/install/reference/breaking-changes#0-73-0). Mail sends
once `AP_SMTP_HOST`, `AP_SMTP_PORT`, `AP_SMTP_USERNAME`, and
`AP_SMTP_PASSWORD` are **all** set (partial configuration falls back to a
log-only sender). TLS is supported. See the
[Production Deployment Checklist](/install/configure-operate/production-checklist#email-smtp)
for the current CE-safe send path, including the `AP_ENVIRONMENT=PRODUCTION`
behavior difference.

### Authentication & SSO

Sign-in providers and SCIM provisioning.

| Variable | Description | Default |
|---|---|---|
| `AP_GOOGLE_CLIENT_ID` | Google OAuth2 client ID for "Sign in with Google". Both this and `AP_GOOGLE_CLIENT_SECRET` must be set for the button to appear; it can no longer be configured from the admin SSO page. | `None` |
| `AP_GOOGLE_CLIENT_SECRET` | Google OAuth2 client secret. Required together with `AP_GOOGLE_CLIENT_ID`. | `None` |
| `AP_CLOUD_AUTH_ENABLED` | Use Inboxfm Connect-hosted OAuth2 apps for piece connections. Set to `false` to disable them. | `true` |
| `AP_SCIM_DEFAULT_PROJECT_ROLE` | Default project role for members added via SCIM group sync. One of `Admin`, `Editor`, `Viewer`. | `Editor` |
| `AP_ALLOW_OPEN_SIGN_UP` | When `true`, anyone can sign up with email/password to an existing platform. When unset, platform sign-up requires the email to be invited to the platform or one of its projects (the first user of a fresh instance signs up regardless). | `None` (invitation required) |
| `AP_FIREBASE_HASH_PARAMETERS` | JSON object of Firebase SCRYPT parameters, used only to verify legacy `$scrypt$`-prefixed password hashes imported from Firebase Auth. Accounts with bcrypt hashes don't need it. | `None` |
| `AP_PROJECT_REPLACE_SIGNING_SECRET` | Dedicated signing secret for project-replace plans (MCP project replacement). Falls back to the `PROJECT_REPLACE_SIGNING_SECRET` env var, then to `AP_JWT_SECRET`. | `None` (falls back to `AP_JWT_SECRET`) |

#### Sign-up & sign-in abuse protection

Every value below has a sane default and needs **no setup** — a fresh self-hosted
instance is already protected. `AP_API_RATE_LIMIT_AUTHN_ENABLED` gates the
underlying `@fastify/rate-limit` plugin (Redis-backed, reusing the same
connection as the job queue); when it's `false`, every rate-limit variable below
is a no-op, same as before this feature existed.

| Variable | Description | Default |
|---|---|---|
| `AP_API_RATE_LIMIT_AUTHN_ENABLED` | Enable IP-based rate limiting on authentication routes (both tiers below). | `true` |
| `AP_API_RATE_LIMIT_AUTHN_MAX` | Requests per window, per IP, for the general authentication tier (`switch-platform`). | `50` |
| `AP_API_RATE_LIMIT_AUTHN_WINDOW` | Window for `AP_API_RATE_LIMIT_AUTHN_MAX`, e.g. `1 minute`. | `1 minute` |
| `AP_API_RATE_LIMIT_AUTHN_ABUSE_MAX` | Requests per window, per IP, for the stricter tier applied to `sign-up`, `sign-in`, and the OTP/password-reset routes (`POST /v1/otp`, `verify-email`, `reset-password`) — the routes a credential-stuffing or account-creation script would actually hit. | `10` |
| `AP_API_RATE_LIMIT_AUTHN_ABUSE_WINDOW` | Window for `AP_API_RATE_LIMIT_AUTHN_ABUSE_MAX`. | `1 minute` |
| `AP_API_SIGN_IN_EMAIL_THROTTLE_ENABLED` | Throttle failed sign-in attempts **per email address**, independent of IP — blunts credential stuffing against one account spread across many IPs/a botnet. | `true` |
| `AP_API_SIGN_IN_EMAIL_THROTTLE_MAX_ATTEMPTS` | Failed sign-in attempts allowed for one email before it's blocked, regardless of source IP. A successful sign-in resets the counter immediately. | `5` |
| `AP_API_SIGN_IN_EMAIL_THROTTLE_WINDOW_SECONDS` | Rolling window (seconds) for `AP_API_SIGN_IN_EMAIL_THROTTLE_MAX_ATTEMPTS`. | `900` (15 minutes) |
| `AP_CAPTCHA_PROVIDER` | Optional CAPTCHA on sign-up: `hcaptcha` or `turnstile`. Unset by default — sign-up behaves exactly as before. Requires `AP_CAPTCHA_SECRET_KEY`; the server refuses to start if only one of the two is set. | `None` |
| `AP_CAPTCHA_SECRET_KEY` | Secret key for the provider above, used server-side to verify the client-supplied token against the provider's `siteverify` endpoint. Only read when `AP_CAPTCHA_PROVIDER` is set. | `None` |
| `AP_CLIENT_REAL_IP_HEADER` | Header used to extract the client's real IP behind a reverse proxy. All IP-based rate limiting, the sign-in email throttle, and audit events key on it; falls back to the socket address when the header is absent. The proxy **must** overwrite or sanitize this header, or clients can spoof their IP and drain rate-limit buckets. | `x-real-ip` |
| `AP_API_RATE_LIMIT_SYNC_ENABLED` | Enable the IP-scoped tier on routes that synchronously run piece code or fan out to AI/search providers inside the API process: `execute`, executions list/create, `knowledge-search`, and the AI-provider routes. Shares the underlying `@fastify/rate-limit` plugin with the authentication tier, but can be toggled independently. | `true` |
| `AP_API_RATE_LIMIT_SYNC_MAX` | Requests per window, per IP, for the sync tier above. | `60` |
| `AP_API_RATE_LIMIT_SYNC_WINDOW` | Window for `AP_API_RATE_LIMIT_SYNC_MAX`, e.g. `1 minute`. | `1 minute` |

#### Request rate limiting & API keys

Per-principal limiters for authenticated traffic (all safe defaults) and the
public-ingress limiter that is on by default.

| Variable | Description | Default |
|---|---|---|
| `AP_API_KEY_RATE_LIMITER_ENABLED` | Enable per-key rate limiting for requests authenticated with an API key (`sk-` platform keys and `cak-` connect keys). Buckets by the key's own id, so one compromised or misbehaving key is capped independently of every other key, project, or IP on the platform. | `false` |
| `AP_API_KEY_RATE_LIMITER_MAX_REQUESTS` | Requests per window, per API key. Only read when `AP_API_KEY_RATE_LIMITER_ENABLED` is `true`. | `120` |
| `AP_API_KEY_RATE_LIMITER_WINDOW_SECONDS` | Window (seconds) for `AP_API_KEY_RATE_LIMITER_MAX_REQUESTS`. | `60` |
| `AP_API_KEY_ROTATION_GRACE_PERIOD_SECONDS` | How long a rotated-out API key keeps authenticating after `rotate` mints its replacement, giving callers a window to swap the new value in before the old one is rejected. Applies to `cak-` connect keys and `sk-` platform keys. | `86400` (24 hours) |
| `AP_PUBLIC_INGRESS_RATE_LIMITER_ENABLED` | Enable the rate limit on the only unauthenticated route that mints executions: `POST /v1/trigger-bindings/:id/run`, bucketed per (binding id, client IP). On by default so a leaked capability URL cannot farm unlimited paid executions. | `true` |
| `AP_PUBLIC_INGRESS_RATE_LIMITER_MAX_REQUESTS` | Requests per window, per binding and IP. Zero, negative, or non-numeric values fall back to this built-in default rather than rejecting everything. | `30` (built-in fallback) |
| `AP_PUBLIC_INGRESS_RATE_LIMITER_WINDOW_SECONDS` | Window (seconds) for `AP_PUBLIC_INGRESS_RATE_LIMITER_MAX_REQUESTS`. Same fallback protection as above. | `60` (built-in fallback) |

<Info>
Enabling `AP_CAPTCHA_PROVIDER` only turns on **server-side verification** — the
client must still collect a token from the provider's widget (hCaptcha or
Cloudflare Turnstile) and send it as `captchaToken` on `POST
/v1/authentication/sign-up`. This repository's own console does not yet render
that widget, so a custom or embedding frontend that enables this must add it.
</Info>
