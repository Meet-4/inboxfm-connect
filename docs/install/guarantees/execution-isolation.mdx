User code from one execution **cannot** read another execution's code, memory, environment, or files. Each operation runs inside its own sandboxed engine process, one operation at a time per sandbox.

<Note>
This is one of the Inboxfm Connect execution guarantees for self-hosted deployments. For the full scope of what does and does not survive a crash, see [Crash Recovery](./crash-recovery).
</Note>

## How it's enforced

Three layers stack:

- **Sandbox.** Each execution's code runs inside a sandbox chosen by `AP_EXECUTION_MODE`: V8/code isolation for multi-tenant, or kernel-namespace isolation. See [Sandboxing](../architecture/sandboxing) for how each mode works and its trade-offs.
- **One operation per sandbox at a time.** The runtime serializes executions per sandbox box: one operation holds a box from acquire to release, and a box that finished a failed operation is torn down and rebuilt rather than reused. Concurrent executions land on different boxes.
- **Admission control.** Per-project execution concurrency caps bound how much of one project's untrusted code runs at once; over-capacity requests are rejected with `429`, not queued.

## Where it stops

- **The container is shared.** All sandboxes live in the app container: there is no per-execution container, filesystem, or memory slice at the orchestrator level. A single execution is bounded by the sandbox's own limits — see [Reserved Resources](./reserved-resources) — not by a container of its own.
- This is **execution** isolation between operations: code, memory, and files. It is distinct from **tenant data isolation** at the query layer (every database query scoped to `projectId` / `platformId`), which is an application-level guarantee enforced in the API, not by the sandbox. For that, see the security documentation.

Choosing the right sandbox is the most important security decision for multi-tenant deployments; a weaker `AP_EXECUTION_MODE` narrows this guarantee.

## Governing configuration

| Variable | Recommended | Effect |
|---|---|---|
| `AP_EXECUTION_MODE` | V8 / code sandboxing (`SANDBOX_CODE_ONLY`) for multi-tenant | How user code is isolated from the host and other executions |

See [Sandboxing Mode](/install/configure-operate/sandboxing) to set the value.
